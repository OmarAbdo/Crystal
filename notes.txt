RESOLVED (were the original "current limitations")
--------------------------------------------------
1. WAL was in-memory only        -> now a durable framed WAL, fsync'd, with
                                    crash recovery (internal/raft/log.go).
2. Node-1-is-leader hardcode      -> removed; real randomized leader election (§5.2).
3. "Is this actually Raft?"       -> yes now: Figure 2 + §5 safety + §7 compaction,
                                    verified by unit + integration tests.

STILL PRIMITIVE (open)
----------------------
- Cluster membership + service discovery are still a hand-written -peers CLI list.
  No dynamic membership (§6 joint consensus).
- Reads are served from any node's state machine -> can be slightly stale under
  a partition. No read leases / linearizable reads yet.
- No pre-vote: a rejoining partitioned node can still force a term bump.
- The /internal endpoints share the same HTTP server as client traffic.
